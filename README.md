# Freim — Сервис учета ошибок программного продукта

Сервис учета и отслеживания ошибок программного продукта на Python с веб-интерфейсом на Django.

## 1. Назначение проекта

Freim — учебное веб-приложение для управления ошибками (дефектами) программного обеспечения.
Проект позволяет регистрировать ошибки, связывать их с пользователями и разработчиками, отслеживать статусы и приоритеты, а также просматривать и фильтровать информацию через современный веб-интерфейс на Django.
Проект развивается поэтапно: консольная версия приложения (ПР1–ПР3) была перенесена на веб-интерфейс Django (ПР5) и переведена на полноценную шаблонную архитектуру (ПР6).

## 3. Предметная область

В системе используются следующие сущности:
- **Ошибка (Error)** — идентификатор, заголовок, описание, серьезность, приоритет, статус, пользователь и ответственный разработчик;
- **Пользователь (User)** — идентификатор, имя, адрес электронной почты;
- **Разработчик (Developer)** — идентификатор, имя, специализация;
- **Статус (Status)** — идентификатор, наименование статуса.

Для предметной области реализованы собственные Python-классы в каталоге `models/`.
На текущем этапе данные хранятся в JSON-файлах в каталоге `data/`. Django ORM и база данных приложения пока не используются.

## 5. Веб-интерфейс

Веб-часть приложения реализована на Django.
Основные страницы:
- главная страница (`/`);
- список ошибок (`/errors/`);
- детальная карточка ошибки (`/errors/<id>/`).

Для формирования страниц используются шаблоны Django. Генерация HTML непосредственно в Python-коде не используется. Представления подготавливают данные и передают их в шаблоны через контекст (`context`), возвращая `render(request, template_name, context)`.

## 6. Django Template Language

В проекте задействованы ключевые возможности Django Template Language:

### Базовый шаблон
Общий каркас страниц расположен в `templates/base.html`. Он определяет DOCTYPE, `<head>`, подключение стилей Bootstrap и собственного CSS, навигацию, контейнер для блоков и подвал с JavaScript.
Дочерние шаблоны наследуют каркас через `{% extends "base.html" %}` и переопределяют блоки:
- `{% block title %}` — заголовок вкладки;
- `{% block content %}` — основное содержимое страницы.

### Включаемые шаблоны (include)
Повторяющиеся части интерфейса вынесены в отдельные включаемые файлы:
- `templates/includes/navigation.html` — общая навигация сайта;
- `templates/errors/includes/error_card.html` — карточка отдельной ошибки;
- `templates/errors/includes/error_status.html` — бейдж статуса ошибки.

Подключение осуществляется через `{% include "..." %}`.

### Контекст
Данные из Python-объектов передаются в словарь контекста и выводятся в шаблоне через `{{ error.title }}`, `{{ error.severity }}` и т.д.

### Циклы и условия
- `{% for error in errors %}` перебирает коллекцию ошибок;
- `{% empty %}` обрабатывает ситуацию пустого списка;
- `{% if error %}` и `{% if error.status.name == ... %}` обеспечивают условное отображение элементов и обработку несуществующих записей (с кодом ответа 404).

## 7. Фильтры шаблонов

В шаблонах применяются стандартные фильтры DTL:
- `{{ errors|length }}` — вывод количества ошибок;
- `{{ error.title|default:"Без названия" }}` — подстановка значения по умолчанию;
- `{{ errors|slice:':5' }}` — срез последних записей на главной странице.

## 8. URL-маршрутизация

Для всех ссылок используются именованные маршруты и пространства имён (`app_name`):
- `{% url 'homepage:index' %}`
- `{% url 'bugtracker:error_list' %}`
- `{% url 'bugtracker:error_detail' error.id %}`

Жестко заданные URL-адреса в шаблонах не используются.

## 9. Статические файлы

Статические файлы приложения организованы в каталоге `homepage/static/homepage/`:
- `css/style.css` — собственные стили карточек, бейджей и логотипа;
- `js/main.js` — клиентский скрипт для динамической установки текущего года в элементе `<span id="current-year"></span>`;
- `img/logo.png` — графический логотип проекта.

Подключение статики выполняется через `{% load static %}` и `{% static 'homepage/...' %}`.

## 10. Хранение данных

На текущем этапе данные приложения хранятся в JSON-файлах:
- `data/errors.json`
- `data/users.json`
- `data/developers.json`
- `data/statuses.json`

Загрузка и сохранение данных выполняются модулем `storage.py`. Django ORM на текущем этапе не используется.

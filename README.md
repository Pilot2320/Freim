# Сервис учета ошибок программного продукта

## Назначение

Консольный прототип сервиса для регистрации и первичной классификации ошибок программного продукта. Сервис помогает команде разработки фиксировать проблему, оценивать ее срочность и готовить понятное описание для дальнейшей работы.

## Целевая аудитория

- тестировщики;
- разработчики;
- руководители проектов и технические специалисты.

## Предметная область

В сервисе учитываются сообщения об ошибках, найденных при тестировании или эксплуатации программного продукта. Для каждой ошибки важны заголовок, описание, серьезность и текущий статус. На следующих этапах записи будут храниться в базе данных и связываться с пользователями, проектами и версиями продукта.

## Основные сущности

- Ошибка: заголовок, описание, серьезность, статус и дата регистрации.
- Пользователь: автор сообщения или ответственный исполнитель.
- Проект: программный продукт, в котором обнаружена ошибка.
- Версия продукта: выпуск, к которому относится ошибка.

## Основные функции

- проверка заполненности заголовка ошибки;
- определение приоритета по уровню серьезности;
- формирование карточки зарегистрированной ошибки.

## План развития

1. На ПР2 добавить коллекции, циклы, функции, обработку файлов и несколько сценариев консольного приложения.
2. На ПР3 реализовать сущности проекта в виде классов.
3. На следующих этапах создать веб-приложение на Django и подключить базу данных.
4. Добавить регистрацию пользователей, роли, CRUD-операции и административный интерфейс.
5. Разработать REST API, автоматические тесты и контейнеризацию приложения.
6. Настроить CI/CD и подготовить приложение к развертыванию.

## Запуск

```text
python main.py
```

Программа демонстрирует начальный сценарий регистрации одной ошибки без использования внешних библиотек.

### Пункт 2. Создание связи между моделями и параметры внешних ключей
* **Показатель**: Продемонстрируйте создание связи между моделями, измените её параметры и объясните результат.
* **Где показать в коде**: Файл `bugtracker/models.py`, модель `Error`:
  ```python
  status = models.ForeignKey(Status, on_delete=models.PROTECT, related_name="errors", verbose_name="Статус")
  developer = models.ForeignKey(Developer, on_delete=models.PROTECT, related_name="errors", verbose_name="Разработчик")
  user = models.ForeignKey(User, on_delete=models.PROTECT, related_name="errors", verbose_name="Пользователь")
  ```
* **Команда в Django Shell**:
  ```python
  python manage.py shell
  from bugtracker.models import Error
  err = Error.objects.select_related("status", "developer", "user").first()
  print(err.title, "-> Статус:", err.status.name, "-> Разработчик:", err.developer.name)
  ```
* **Что сказать преподавателю**:
  - `models.ForeignKey` реализует реляционную связь «многие к одному» (много ошибок могут иметь один статус или одного ответственного разработчика).
  - `on_delete=models.PROTECT` запрещает удаление связанного объекта (например, разработчика или статуса), пока в базе есть ссылающиеся на него ошибки, предотвращая появление «висячих» внешних ключей и нарушение ссылочной целостности (вызывает исключение `ProtectedError`).
  - `CASCADE` удалил бы все связанные ошибки вслед за разработчиком, а `SET_NULL` обнулил бы поле (требует `null=True`).


### Пункт 6. Изменение существующего объекта через ORM
* **Показатель**: Продемонстрируйте изменение существующего объекта через ORM, измените присваиваемое значение и объясните результат.
* **Команда в Django Shell**:
  ```python
  from bugtracker.models import Error
  err = Error.objects.get(pk=1)
  old_title = err.title
  err.title = "Обновленный заголовок через ORM"
  # Изменение в памяти не попадает в БД до вызова save():
  err.save(update_fields=["title"])
  err.refresh_from_db()
  print("Новый заголовок из БД:", err.title)
  # Возвращаем исходный заголовок:
  err.title = old_title
  err.save(update_fields=["title"])
  ```
* **Что сказать преподавателю**:
  - Изменение атрибутов объекта модели в Python происходит в оперативной памяти. Запрос `UPDATE` в базу данных отправляется только при явном вызове `save()` или при использовании массового метода `QuerySet.update()`.
  - Аргумент `update_fields=["title"]` оптимизирует запрос, обновляя только указанную колонку.

### Пункт 8. Получение записей через QuerySet и фильтрация filter()
* **Показатель**: Продемонстрируйте получение записей через QuerySet, добавьте условие фильтрации и объясните результат.
* **Команда в Django Shell**:
  ```python
  from bugtracker.models import Error
  # Все записи:
  all_errors = Error.objects.all()
  print("Всего:", all_errors.count())

  # Фильтрация по серьезности:
  crit = Error.objects.filter(severity="критическая")
  print("Критических:", crit.count())
  for e in crit:
      print(" -", e.id, e.title)
  ```
* **Что сказать преподавателю**:
  - `QuerySet` является «ленивым» (lazy evaluation): SQL-запрос выполняется только тогда, когда данные реально запрашиваются (итерация в цикле, вызов `count()`, срез, сериализация в шаблон).
  - Метод `filter()` формирует клаузу `WHERE severity = 'критическая'`.

  ```python
  from bugtracker.models import Developer
  # Разработчики со всеми своими ошибками (включая тех, у кого 0 ошибок):
  devs = Developer.objects.annotate(cnt=Count("errors"))
  ```

### Пункт 29. Получение одной записи через get() и обработка исключений
* **Показатель**: Продемонстрируйте получение одной записи через get(), измените условие поиска и объясните результат.
* **Команда в Django Shell**:
  ```python
  from bugtracker.models import Error
  # Успешное получение по ID:
  err = Error.objects.get(pk=1)
  print("Найдена:", err.title)

  # Исключение DoesNotExist при отсутствии:
  try:
      Error.objects.get(pk=99999)
  except Error.DoesNotExist:
      print("Поймано исключение: Error.DoesNotExist!")

  # Исключение MultipleObjectsReturned, если найдено больше 1 записи:
  try:
      Error.objects.get(severity="критическая")
  except Error.MultipleObjectsReturned:
      print("Поймано исключение: Error.MultipleObjectsReturned!")
  ```
* **Что сказать преподавателю**:
  - `get()` ожидает возврата ровно одного объекта. Если объект не найден, выбрасывается `Model.DoesNotExist`; если найдено более одного объекта — `Model.MultipleObjectsReturned`.
